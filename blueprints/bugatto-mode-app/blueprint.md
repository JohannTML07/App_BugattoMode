## 1. Project Overview & Non-Goals

### Vision
Bugatto Mode App es una herramienta interna modular diseñada para administradores de un taller de confección. Permite gestionar la nómina a destajo (piece-rate) de los empleados, con una liquidación semanal que consolida el trabajo no pagado en una "cuenta semanal" y genera un recibo en PDF. 

### Users
| Persona | What they come to do | Frequency |
|---|---|---|
| Administrador del Taller | Registrar el trabajo a destajo y emitir recibos semanales de nómina | Diario / Semanal |

### Goals — v1 scope
1. Autenticación de administradores a través de Supabase Auth.
2. Gestión CRUD de Empleadas y Conceptos de Pago.
3. Registro de Trabajo Realizado, copiando el precio unitario del concepto en el momento del registro.
4. Liquidación semanal que cierra el trabajo no pagado en una `cuenta_semanal` y genera un recibo PDF.

### Non-Goals — explicitly out of scope for v1
| Not building | Why not now | Revisit when |
|---|---|---|
| Gestión de clientes | El foco actual es puramente el pago a los empleados y la contabilidad interna. | Cuando el taller necesite facturación externa. |
| Gestión de gastos | Incrementa la complejidad del esquema. | Después de que el sistema de nóminas esté estable. |
| Múltiples roles de usuario | Todos los usuarios autenticados son administradores confiables del taller. | Si el taller crece y necesita supervisores con acceso limitado. |

### Success metrics
| Metric | Target | How measured |
|---|---|---|
| Cuentas semanales liquidadas | 100% de registros pagados al cierre de semana | Consultando registros sin `cuenta_semanal_id` |

## 2. Tech Stack

**Runtime track: ts-node.** 

| Layer | Choice | Why this, over what |
|---|---|---|
| Language / runtime | Node.js / TypeScript | Tipado estático completo de extremo a extremo frente a JS plano. |
| Framework | Next.js (App Router) | Ecosistema rico en React, soporte robusto de Server Components. |
| Styling | Tailwind CSS | Sistema de utilidad rápido con consistencia, en lugar de CSS personalizado. |
| Component layer | React / shadcn/ui | Primitivas accesibles y pre-estilizadas que aceleran el desarrollo. |
| Database | PostgreSQL (Supabase DB) | SQL relacional para garantizar la integridad financiera (transacciones, constraints). |
| ORM / data access | Drizzle ORM | Fuerte tipado SQL-first, preferido para lógica de datos explícita frente a abstracciones pesadas. |
| Auth | Supabase Auth | Manejado en la misma plataforma que la base de datos, con RLS integrado. |
| Background work | NOT APPLICABLE | No se requiere trabajo en segundo plano para V1. |
| Payments | NOT APPLICABLE | No se reciben pagos en la app. |
| File storage | NOT APPLICABLE | Los PDFs se generan al vuelo, no se almacenan permanentemente. |
| Email / notifications | NOT APPLICABLE | La liquidación se imprime o descarga como PDF. |
| Hosting | Netlify | Despliegue nativo sin configuración pesada de infraestructura. |
| Package manager | pnpm | Resoluciones estrictas de `node_modules` y cachés veloces. |

| Field | Type | Constraints | Notes |
|---|---|---|---|

| fecha_inicio | date | not null | |
| fecha_fin | date | not null | |
| total | integer | not null | Total pagado en la semana en centavos |
| estado | text | not null, default 'cerrada' | |
| created_at | timestamptz | not null, default now() | |

**trabajo_realizado**
| Field | Type | Constraints | Notes |
|---|---|---|---|
| id | uuid | PK, default gen_random_uuid() | |
| empleada_id | uuid | FK(empleada.id), not null | |
| concepto_id | uuid | FK(concepto_pago.id), nullable | Puede ser null si el concepto se borra |
| precio_unitario_historico | integer | not null | Captura de precio unitario en centavos para mitigar riesgos |
| cantidad | integer | not null | Número de unidades |
| total | integer | not null | precio * cantidad (en centavos) |
| fecha | date | not null | |
| cuenta_semanal_id | uuid | FK(cuenta_semanal.id), nullable | Null = trabajo no pagado |
| created_at | timestamptz | not null, default now() | |

### Relationships
- empleada —(1:N)→ trabajo_realizado
- concepto_pago —(1:N)→ trabajo_realizado
- empleada —(1:N)→ cuenta_semanal
- cuenta_semanal —(1:N)→ trabajo_realizado

### Indexes
| Table | Index | Why |
|---|---|---|
| trabajo_realizado | idx_trabajo_cuenta | Búsqueda eficiente de trabajos no pagados (`cuenta_semanal_id IS NULL`) |
| cuenta_semanal | idx_cuenta_empleada | Búsqueda de cuentas por empleada |

### Schema
```typescript
import { pgTable, uuid, text, integer, date, timestamp, index } from 'drizzle-orm/pg-core';
import { sql } from 'drizzle-orm';

export const empleada = pgTable('empleada', {
  id: uuid('id').primaryKey().defaultRandom(),
  nombre: text('nombre').notNull(),
  createdAt: timestamp('created_at', { withTimezone: true, mode: 'string' }).defaultNow().notNull(),
  deletedAt: timestamp('deleted_at', { withTimezone: true, mode: 'string' }),
});

export const conceptoPago = pgTable('concepto_pago', {
  id: uuid('id').primaryKey().defaultRandom(),
  nombre: text('nombre').notNull(),
  precioUnitario: integer('precio_unitario').notNull(),
  createdAt: timestamp('created_at', { withTimezone: true, mode: 'string' }).defaultNow().notNull(),
});

export const cuentaSemanal = pgTable('cuenta_semanal', {
  id: uuid('id').primaryKey().defaultRandom(),
  empleadaId: uuid('empleada_id').notNull().references(() => empleada.id),
  fechaInicio: date('fecha_inicio').notNull(),
  fechaFin: date('fecha_fin').notNull(),
  total: integer('total').notNull(),
  estado: text('estado').notNull().default('cerrada'),
  createdAt: timestamp('created_at', { withTimezone: true, mode: 'string' }).defaultNow().notNull(),
}, (t) => [
  index('idx_cuenta_empleada').on(t.empleadaId)
]);

export const trabajoRealizado = pgTable('trabajo_realizado', {
  id: uuid('id').primaryKey().defaultRandom(),
  empleadaId: uuid('empleada_id').notNull().references(() => empleada.id),
  conceptoId: uuid('concepto_id').references(() => conceptoPago.id, { onDelete: 'set null' }),
  precioUnitarioHistorico: integer('precio_unitario_historico').notNull(),
  cantidad: integer('cantidad').notNull(),
  total: integer('total').notNull(),
  fecha: date('fecha').notNull(),
  cuentaSemanalId: uuid('cuenta_semanal_id').references(() => cuentaSemanal.id, { onDelete: 'set null' }),
  createdAt: timestamp('created_at', { withTimezone: true, mode: 'string' }).defaultNow().notNull(),
}, (t) => [
  index('idx_trabajo_cuenta').on(t.cuentaSemanalId)
]);
```

## 9. BUILD ORDER

### Step 1: Inicialización
- **Goal:** Crear proyecto Next.js y tipar stack.
- **Files touched:** `package.json`, `next.config.ts`, `tsconfig.json`
- **Do:** Ejecutar inicialización, configurar dependencias de next y typescript.
- **Done when:** `pnpm next build` corre y sale 0.
- **Verify:** `pnpm build; test $? -eq 0`
- **Checkpoint:** `git add -A && git commit -m "step 01: init" && git tag step-01-init`

### Step 2: Configuración de Base de datos
- **Goal:** Conectar a Postgres via Drizzle e iniciar modelo.
- **Files touched:** `src/lib/db/schema.ts`, `drizzle.config.ts`, `.env`
- **Do:** Escribir el esquema, correr migraciones.
- **Done when:** `pnpm drizzle-kit generate` crea los esquemas.
- **Verify:** `pnpm exec drizzle-kit generate; test $? -eq 0`
- **Checkpoint:** `git add -A && git commit -m "step 02: db" && git tag step-02-db`
