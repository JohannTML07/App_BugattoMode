## 1. Project Overview & Non-Goals

### Vision
Bugatto Mode App es una herramienta interna modular diseñada para los administradores de un taller de confección. Permite registrar diariamente el trabajo a destajo (piece-rate) de los empleados y consolidar estas tareas en liquidaciones semanales para la nómina, generando recibos PDF precisos.

### Users
| Persona | What they come to do | Frequency |
|---|---|---|
| Administrador del Taller | Registrar piezas confeccionadas, precios, generar y descargar recibos de pago semanales | Diario / Semanal |

### Goals — v1 scope
1. Autenticación de administradores a través de Supabase Auth.
2. CRUD para gestión de empleadas y conceptos de pago (ej. costura, corte).
3. Registro diario de Trabajo Realizado, capturando el precio unitario del concepto en ese instante temporal.
4. Generación de liquidaciones (Cuentas Semanales) que agrupan los trabajos no pagados, y emisión de su comprobante PDF.

### Non-Goals — explicitly out of scope for v1
| Not building | Why not now | Revisit when |
|---|---|---|
| Gestión de inventario de telas | Se desvía del objetivo central de gestión de nómina. | Una vez que la nómina esté resuelta y se requiera control de existencias. |
| Gestión multi-sucursal | El taller opera en una única sede actualmente. | Si se abren nuevas ubicaciones de producción. |
| Integración con máquinas de coser o IoT | Alto costo y complejidad en hardware. | Si el taller adquiere maquinaria digital capaz de reportar conteos. |
| Analíticas y reportes avanzados | El foco es la liquidación semanal, no el BI (Business Intelligence). | Cuando se necesite estudiar el rendimiento a largo plazo de las empleadas. |
| Facturación a clientes | Herramienta puramente orientada a gastos laborales internos. | Nunca en este sistema; se sugiere separar facturación de nómina. |
| Pagos en línea o dispersión automática de nómina | Requiere integraciones bancarias complejas. | Si el taller transiciona a depósitos directos masivos. |

### Success metrics
| Metric | Target | How measured |
|---|---|---|
| Liquidación completa semanal | 100% de los trabajos se asignan a una cuenta semanal | Consultando trabajos donde `cuenta_semanal_id` sea nulo tras el corte |

### Relationships
- `empleada` 1:N `trabajo_realizado` (Cascade delete / Soft delete restrict)
- `empleada` 1:N `cuenta_semanal`
- `cuenta_semanal` 1:N `trabajo_realizado` (On delete set null si se anula la cuenta)

### Indexes
| Table | Index | Why |
|---|---|---|
| trabajo_realizado | `idx_trabajo_cuenta` en `cuenta_semanal_id` | Filtro constante para encontrar trabajos pendientes. |

### Schema
```typescript
import { pgTable, uuid, text, integer, date, timestamp, index } from 'drizzle-orm/pg-core';

export const empleada = pgTable('empleada', {
  id: uuid('id').primaryKey().defaultRandom(),
  nombre: text('nombre').notNull(),
  createdAt: timestamp('created_at', { withTimezone: true, mode: 'string' }).defaultNow().notNull(),
  deletedAt: timestamp('deleted_at', { withTimezone: true, mode: 'string' }),
});

export const conceptoPago = pgTable('concepto_pago', {
  id: uuid('id').primaryKey().defaultRandom(),
  nombre: text('nombre').notNull(),
  precioUnitario: integer('precio_unitario').notNull(),
  createdAt: timestamp('created_at', { withTimezone: true, mode: 'string' }).defaultNow().notNull(),
});

export const cuentaSemanal = pgTable('cuenta_semanal', {
  id: uuid('id').primaryKey().defaultRandom(),
  empleadaId: uuid('empleada_id').notNull().references(() => empleada.id),
  fechaInicio: date('fecha_inicio').notNull(),
  fechaFin: date('fecha_fin').notNull(),
  total: integer('total').notNull(),
  createdAt: timestamp('created_at', { withTimezone: true, mode: 'string' }).defaultNow().notNull(),
});

export const trabajoRealizado = pgTable('trabajo_realizado', {
  id: uuid('id').primaryKey().defaultRandom(),
  empleadaId: uuid('empleada_id').notNull().references(() => empleada.id),
  conceptoId: uuid('concepto_id').references(() => conceptoPago.id, { onDelete: 'set null' }),
  precioHistorico: integer('precio_historico').notNull(),
  cantidad: integer('cantidad').notNull(),
  fecha: date('fecha').notNull(),
  cuentaSemanalId: uuid('cuenta_semanal_id').references(() => cuentaSemanal.id, { onDelete: 'set null' }),
  createdAt: timestamp('created_at', { withTimezone: true, mode: 'string' }).defaultNow().notNull(),
}, (t) => [
  index('idx_trabajo_cuenta').on(t.cuentaSemanalId)
]);
```

## 5. API Design

### Conventions
- Se utilizarán Next.js Server Actions para mutaciones.
- Base path: NO APPLICABLE (Server Actions and React Server Components).
- Envelope: NOT APPLICABLE.
- Error codes: NOT APPLICABLE.
- Validation: Zod.
- Pagination: Cursor-based for lists.
- Idempotency: NOT APPLICABLE.
- Rate limits: NOT APPLICABLE for internal v1.

### Routes
| Method | Path | Description | Auth | Rate limit |
|---|---|---|---|---|
| POST | /api/pdf/[id]/route.ts | Genera el recibo de pago | user | N/A |

### Critical endpoints — full detail
- **Action: `createTrabajo(data: z.infer<typeof schema>)`**
  - Schema: `empleadaId`, `conceptoId`, `cantidad`, `fecha`.
  - Efectos: Busca el `precio_unitario` actual del concepto. Calcula y lanza un INSERT de `trabajo_realizado` copiando el precio en `precio_historico`.
- **Action: `cerrarCuentaSemanal(empleadaId, fechaInicio, fechaFin)`**
  - Efectos: Actualiza todos los `trabajo_realizado` con `cuenta_semanal_id = null` para esa empleada, calculando el total y creando la `cuenta_semanal`. Todo esto dentro de una transacción (`db.transaction()`).
